# AIツール比較メモ

AIツールの名前・月額料金・メモを登録し、一覧・検索・並べ替え・編集・削除・CSV出力ができる、ブラウザだけで動くアプリケーションです。データはブラウザの localStorage に保存されます。

## 使用技術

- HTML5
- CSS3（Flexbox / Grid、メディアクエリによるレスポンシブ対応）
- Vanilla JavaScript（ES2022）
- JSDoc ＋ `// @ts-check`（TypeScript の JavaScript 型チェック機能）
- localStorage
- テスト: Node.js 標準の `node:test`（開発時のみ。外部ライブラリなし）

フレームワーク・外部ライブラリ・CDN・外部 API は使用していません。

## ファイル構成

```text
ai-tool-memo/
├── index.html       画面構造（フォーム・一覧・通知領域）
├── style.css        スタイル（PC は表形式、幅 720px 以下はカード形式）
├── script.js        アプリ本体（検証・データ操作・検索/ソート・CSV・永続化・描画）
├── script.test.js   script.js の純粋関数に対する自動テスト（任意実行）
└── README.md        本書
```

`script.js` の内部構成は次のとおりです。全体を即時関数で包み、グローバルに公開するのはテスト用の `AiToolMemo`（純粋関数の集合）だけです。アプリの状態は `startApp()` のクロージャ内に閉じ込めています。

| 区分 | 主な関数 |
| --- | --- |
| 実行時の型検証 | `parseToolList` / `parseTool` |
| 入力検証 | `validateToolInput` / `validateName` / `validateMonthly` |
| データ操作 | `createInitialTools` / `addTool` / `updateTool` / `removeTool` / `createToolId` |
| 検索・ソート | `filterTools` / `sortTools` / `getVisibleTools` / `parseSortOrder` |
| CSV 出力対象の選択 | `getSelectedTools` / `selectAllTools` / `getSelectAllState` / `pruneSelection` |
| CSV | `buildCsv` / `escapeCsvField` / `neutralizeCsvFormula` / `downloadTextFile` |
| 永続化 | `openStorage` / `loadTools` / `saveTools` / `initPersistence` / `persistTools` |
| 表示 | `renderList` / `renderSelection` / `renderFormMode` / `renderStorageState` / `renderFieldErrors` |

データ更新はすべて `commitTools()` を通り、「検証 → 新しい配列を作成 → メモリ更新 → 保存 → 再描画 → 結果通知」の順で処理します。データ操作関数は元の配列を変更しません。

## 起動方法

1. このフォルダをダウンロード（またはクローン）します。
2. `index.html` をブラウザ（Chrome / Edge / Firefox / Safari の最新版）で直接開きます。

npm install・ビルド・サーバーの起動は不要です。

GitHub Pages でも公開しています: https://taka10-web.github.io/ai-tool-memo/

## 機能説明

| 機能 | 操作方法 |
| --- | --- |
| 一覧表示 | 初回は初期データ 3 件（Alpha / Beta / Gamma）を表示します。料金は `3,000円` の形式です。 |
| 追加 | 左（スマートフォンでは上）のフォームに入力して「追加する」を押します。 |
| 編集 | 一覧の「編集」を押すと、フォームに現在の値が入り「〜を編集中」の表示に変わります。「更新する」で確定し、「編集をキャンセル」または Esc キーで取り消します。 |
| 削除 | 「削除」を押し、確認ダイアログで OK を選ぶと削除します。 |
| 検索 | 名前・メモを部分一致で検索します。大文字・小文字、全角・半角の違いは区別しません。前後の空白は無視し、空欄なら全件を表示します。 |
| 並べ替え | 「登録順」「月額料金が安い順（昇順）」「月額料金が高い順（降順）」から選びます。同額の場合は登録順を保ちます。検索と組み合わせて使えます。 |
| CSV 出力対象の選択 | 一覧の各行のチェックボックスで、CSV に出力するデータを選びます。一覧上部の「全件選択」で、登録済みの全件をまとめて選択・解除できます。一部だけ選択しているときは、「全件選択」が中間状態（−）で表示されます。 |
| CSV ダウンロード | 「選択した N件をCSV出力」で、選択中のデータを出力します。 |
| 初期状態へ戻す | 確認後、データを初期 3 件に戻し、検索条件・並び順・編集状態も初期化します。 |

編集・削除の対象は表示順ではなく内部 ID で特定するため、検索・並べ替えの後でも正しいデータを操作できます。

## 入力ルール

| 項目 | ルール |
| --- | --- |
| 名前 | 必須。前後の空白は除去します。空欄・空白のみは不可です。大文字・小文字を区別せずに重複を判定し、同名は登録できません（編集時は編集対象自身を除外）。 |
| 月額料金 | 必須。0 以上の整数（円）で、0 円も登録できます。負数・小数・数字以外の文字（`NaN`・`Infinity`・`1e3`・`3,000`・`3000円` など）・`Number.MAX_SAFE_INTEGER`（9,007,199,254,740,991）を超える値は登録できません。全角数字は半角に変換して受け付けます。 |
| メモ | 任意。空欄・日本語・改行を入力できます。 |

- 空欄判定は数値変換の前に行うため、空欄が `0` として扱われることはありません。
- 料金欄は `type="number"` ではなく `type="text" inputmode="numeric"` を使っています。`type="number"` では不正な文字列の値が空文字になり、空欄と区別できないためです。
- 入力エラーがある場合はデータを変更せず、入力値を残したまま、該当欄の下に日本語のメッセージを表示します（`aria-invalid` と `aria-describedby` で欄とメッセージを関連付けています）。

## データ保存

- 保存先: localStorage のキー `ai-tool-memo:tools:v1`（本アプリ専用）
- 追加・編集・削除・リセットのたびに保存します。全件削除した状態（空配列）も正しいデータとして保存・復元し、初期データを勝手に復活させません。
- 読み込んだデータは信用せず、配列であること、各要素の型、ID・名前の重複、料金が 0 以上の安全な整数であることを実行時に検証します。

### 保存できない場合の挙動

| 状況 | 挙動 |
| --- | --- |
| localStorage が利用できない | 初期データで一時的に利用できます。画面上部に「再読み込みで変更が失われる」旨を表示し、ヘッダーに「保存停止中」と表示します。 |
| 保存に失敗した（容量超過など） | メモリ上の変更は保持し、「保存に失敗しました（未保存）」と通知して、ヘッダーに「未保存の変更あり」と表示します。次回の保存に成功すると、この表示は解除されます。 |
| 保存データが破損している／構造・型が不正／ID や名前が重複している | 初期データで一時的に動作します。破損データを無断で上書きしないよう自動保存を停止し、その旨を画面に表示します。 |

保存に失敗した場合は「保存しました」と表示しません。原因の詳細は、開発者向けに `console.error` へ記録します。

### 初期化方法

「初期状態へ戻す」を押して確認すると、本アプリのキーだけを初期 3 件で上書きします。破損データがある場合も、この明示的な操作によって保存を再開できます（確認ダイアログでも上書きされることを示します）。他のアプリの localStorage データは削除しません。

## CSV 出力仕様

### 出力対象の選択

- 出力するのは、チェックボックスで選択したデータです。初期状態ではどれも選択されていません。
- 「全件選択」は、検索で絞り込んでいる場合も含め、**登録済みの全件**を対象にします（全件を出力するための操作として扱うためです）。画面に表示されていない行が選択されていても、「N件を選択中」の件数表示で確認できます。
- 1 件も選択せずに出力しようとすると、選択を促すメッセージを表示し、ファイルは作成しません。
- 行は表示順ではなく登録順で出力します。
- 選択状態は保存しません（再読み込みで解除されます）。データを削除すると選択からも外れ、新しく追加したデータは未選択の状態で登録されます。「初期状態へ戻す」を実行すると選択は解除されます。
- 選択は内部 ID で管理しているため、検索・並べ替えの前後で選択がずれることはありません。

### ファイル形式

- 文字コード: UTF-8（BOM 付き）、改行: CRLF
- 列: `名前,月額料金（円）,メモ`（ヘッダーあり。`buildCsv` は 0 件でもヘッダーのみを出力できますが、画面からは 1 件以上選択したときだけ出力します）
- 月額料金は桁区切りや「円」を付けない数値です。
- カンマ・ダブルクォート・改行を含む値は、RFC 4180 に従い `"` で囲み、`"` は `""` にします。

### CSV インジェクション対策（エクスポート値が変わる場合があります）

名前・メモが `=` `+` `-` `@`（全角の `＝` `＋` `－` `＠` を含む）で始まる場合、先頭に `'`（シングルクォート）を付けて出力します。先頭の空白・全角空白・制御文字の後にこれらの記号が続く場合や、値がタブ・改行で始まる場合も同様です。

例: `=1+1` → `'=1+1`、`-メモ` → `'-メモ`、` =SUM(A1)` → `' =SUM(A1)`

このため、該当する値は **CSV 上の値がアプリ内の値と 1 文字異なります**。アプリ内のデータ自体は変更しません。

## セキュリティ

- ユーザー入力（localStorage から復元したデータを含む）は、すべて `textContent` で表示します。`innerHTML` は使用していません。
- インラインイベントハンドラーと `eval()` は使用していません。
- 編集・削除ボタンの識別には `data-id` を使い、ID を CSS セレクタへ埋め込みません。
- `<img src=x onerror=alert(1)>` のような文字列も、テキストとしてそのまま表示されることを確認しています。

## 型チェック

### JSDoc ＋ `@ts-check` を採用した理由

「TypeScript を使わず、ビルド不要」という制約の中でも、データ構造（`AITool`・`AppState`・`PersistenceState` など）や関数の入出力を静的に検査し、null 参照や型の取り違えを防ぐためです。`any` は使っていません。`JSON.parse` の結果は `unknown` として受け取り、`parseToolList` で実行時に検証してから型付きデータに変換します。DOM 要素は `getRequiredElement` で存在と種類を確認し、欠けている場合は原因が分かるエラーを投げます（起動時に捕捉し、画面とコンソールに表示します）。

### 確認方法

エディタ（VS Code など）で `script.js` を開くと、`// @ts-check` により型エラーが表示されます。CLI で確認する場合は次のコマンドを使います（Node.js が必要で、`npx` が TypeScript を一時的に取得します。アプリ自体の動作には不要です）。

```sh
npx -p typescript@5.6.3 tsc --noEmit --allowJs --checkJs --strict --target es2022 --lib es2022,dom,dom.iterable script.js
```

実施結果: エラー 0 件（TypeScript 5.6.3、`--strict`）

### 確認中に見つかり修正した問題

1. スマートフォン幅で、カード内の編集・削除ボタンが横いっぱいに広がらない（CSS の詳細度の問題）。
2. PC 幅で、最大桁の金額が隣のメモ列へはみ出す（`white-space: nowrap` が原因）。
3. 操作ボタンのセル（`td`）自体を flex にしたことで、表の罫線がずれる。ボタンは内側の `div` で並べる構造に変更しました。
4. `main` の上余白が `.container` の `padding` 指定で打ち消され、ヘッダー直下に余白がない。

5. （CSV 選択機能の追加時）スマートフォンのカード表示で、チェックボックスがカードの先頭に 1 行を占めて間延びしていたため、カード右上に配置し直しました。

いずれも修正後にブラウザで再確認しました。

## 既知の制約

- データはブラウザごと・端末ごとに保存されます。別のブラウザや端末とは同期しません。
- 同じアプリを複数のタブで同時に編集すると、後から保存したタブの内容で上書きされます（タブ間の同期は行いません）。
- Content-Security-Policy の meta タグは付けていません。`file://` で開いた場合、ブラウザによっては `'self'` が同じフォルダのファイルに一致せず、スクリプトが読み込めなくなるためです。XSS への対策は、安全な DOM API の使用で担保しています。
